## FUNC-001: 다중 스레드 수집·목적별 분배

- 관련 요구사항: FR-001·002·007~009·012·013
- 관련 Story: [US-001](user_stories/US-001_rt_concurrent_capture.md)
- 관련 Milestone: 없음
- 상태: Approved(설계 기준선, 구현/검증 전)

### 기본 흐름

1. 등록한 생산자가 논리 채널로 기록을 제시한다.
2. 정책과 자원 예산에 따라 수락 여부를 결정하고 실패를 관측할 수 있게 한다.
3. 수락한 기록은 선택한 출력으로 처리하며 RT 호출은 완료를 기다리지 않는다.

### 예외·미정 계약

포화·저장 장애는 수락/실패·폐기로 구분한다. 데이터 수명·순서·버퍼/worker 구조·API는 설계에서 결정한다.

### 수락 기준

관련 Story의 승인된 설계 기준선 AC를 따른다. 수치·실행 조건은 [요구사항 §12](requirement_spec.md#12-초기-통합-사양안--제안-01)의 승인된 설계 기준선과 미결 조건을 함께 확인한다.

## FUNC-002: 파일 운영·보존·완료 상태 확인

- 관련 요구사항: FR-003·007·009·011·018
- 관련 Story: [US-002](user_stories/US-002_retention_and_recovery.md)
- 관련 Milestone: 없음
- 상태: Approved(설계 기준선, 구현/검증 전)

### 기본 흐름

1. 적용 환경의 용량/기간·보존 모드에 따라 파일을 기록·회전·보존한다.
2. 수락·쓰기·동기화 완료량과 미처리/실패를 각각 관측한다.
3. 정상 종료·중단·공간 부족 시 완료/복구 범위를 보고한다.
4. 명시적으로 활성화한 FR-018 옵션에서 미니 UPS 등의 전원 이상 예고를 받으면 중요 파일부터 긴급 기록한다. 기본값은 비활성(Human 확정)이다. 약 3초는 UPS 신호 발생부터 실제 전원 차단까지의 전체 시간이며 신호 전달·종료 여유를 포함한다.

### 예외·미정 계약

파일 형식·기본값·중요도/포화·복구 상세는 미정이며 기존 ADR-003·004를 유지한다.

FR-018의 중요 파일 순위·보호할 미동기화량·영속 동기화/복구 완료 경계·신호 어댑터와 긴급 입력/출력 정책은 [요구사항 §17](requirement_spec.md#17-전원-이상-시-중요-파일-우선-긴급-기록)·인터페이스 §12의 검토안이다. 기능 추가 요청을 세부 전략/시간 보장의 승인으로 취급하지 않는다. US-002의 추가 AC 초안은 기존 승인 AC와 구분한다.

### 수락 기준

관련 Story의 승인된 설계 기준선 AC를 따른다. 수치·실행 조건은 [요구사항 §12](requirement_spec.md#12-초기-통합-사양안--제안-01)의 승인된 설계 기준선과 미결 조건을 함께 확인한다.

## FUNC-003: 조회·재생·DB/모니터링 활용

- 관련 요구사항: FR-004~006·010
- 관련 Story: [US-003](user_stories/US-003_query_replay_integrations.md)
- 관련 Milestone: 없음
- 상태: Approved(설계 기준선, 구현/검증 전)

### 기본 흐름

1. 소비자가 선택한 시간/데이터 범위의 조회·재생·구독을 요청한다.
2. 기록/DB/전송 경로에서 정한 완료 경계에 맞춰 데이터를 제공한다.
3. 동시 수집 영향과 경로별 실패·지연을 관측한다.

### 예외·미정 계약

클라이언트 형태·DB/프로토콜·세부 조회/재생 계약은 미정. ROS 2 검토는 T1이다.

### 수락 기준

관련 Story의 승인된 설계 기준선 AC를 따른다. 수치·실행 조건은 [요구사항 §12](requirement_spec.md#12-초기-통합-사양안--제안-01)의 승인된 설계 기준선과 미결 조건을 함께 확인한다.

## FUNC-004: 관측·리포트·점검·개발자 조절

- 관련 요구사항: FR-014·016·017
- 관련 Story: [US-004](user_stories/US-004_observability_and_tuning.md)
- 관련 Milestone: 없음
- 상태: Approved(설계 기준선, 구현/검증 전)

### 기본 흐름

1. 운영 부하·단계별 완료·자원 상태를 제한된 비용으로 관측한다.
2. 검증된 능력과 관측/추정을 구분해 병목·여유·잔여 시간을 설명한다.
3. 개발자가 기록량·주기·대상을 조절하거나 별도 점검을 선택한다.
4. 조건과 설정을 연결해 변경 전후 효과·의도적 생략·손실을 비교한다.

### 예외·미정 계약

미측정/만료된 기준과 추정 한계를 표시하며 운영 중 고부하 시험이나 자동 제한을 기본 동작으로 가정하지 않는다.

### 수락 기준

관련 Story의 승인된 설계 기준선 AC를 따른다. 수치·실행 조건은 [요구사항 §12](requirement_spec.md#12-초기-통합-사양안--제안-01)의 승인된 설계 기준선과 미결 조건을 함께 확인한다.

## FUNC-005: 크로스 플랫폼 공통 기능과 기록 교환

- 관련 요구사항: NFR-007·CON-002, 공통 FR 범위
- 관련 Story: [US-005](user_stories/US-005_cross_platform_support.md)
- 상태: Approved(지원 방향), 상세 OS 매트릭스·실행 검증 전

Linux·macOS·Windows에서 라이브러리/클라이언트의 공통 기록·활용·관측/조절 경로를 제공한다. 공통 API와 플랫폼별 시각·파일/동기화·실행·계측을 분리하고 미지원 기능은 명시한다. 실제 빌드/실행·기록 교환을 검증하며 R1의 Linux PREEMPT_RT 수치를 다른 OS의 실측으로 취급하지 않는다. 구체 지원 버전·CPU/MSRV·시험 범위는 [요구사항 §16](requirement_spec.md#16-크로스-플랫폼-지원과-검증-범위)의 계획을 따른다.
