# US-002 — 예산에 맞춘 파일 운영과 완료 상태 확인

- 관련 Intent: INT-001
- 관련 Milestone: MS-003·006·007 (계획 승인)
- 상태: Approved — 기존 AC-1~5 설계 기준선 승인. FR-018 선택 옵션·기본 비활성 및 AC-6~10 승인(2026-10-26 ADR-008 기준선 채택). 구현·검증 전
- 우선순위: Must(기능 방향 기준)
- 관련 요구사항: FR-003·007·009·011·018 / NFR-003·005
- 갱신: 2026-10-25 / AI

## 사용자 요구

로봇 운영자는 실제 SSD와 용량 예산에 맞춰 기록을 보존하고 저장 장애나 중단의 영향을 확인하기를 원한다.

추가 요구: 미니 UPS 등의 전원 이상 신호 발생부터 실제 전원 차단까지 전체 약 3초 동안, 중요 파일의 미기록 내용을 우선 저장하기를 원한다(Human 확인).

Human 확정 사용 정책: 선택 옵션으로 제공하며 기본값은 비활성이다. 활성화한 구성에 긴급 저장 목표를 적용한다.

## 수락 기준 — 설계 기준선

- AC-1: 연속·순환·이벤트 전후 보존을 선택할 수 있다. 기본 모드·개별 설정값은 설계에서 결정한다.
- AC-2: 수락·파일 쓰기·영속 동기화 완료와 실패/미처리량을 구분해 보고한다.
- AC-3: 파일 회전·보존과 동시 부하에서 설정한 자원 상한을 지키는지 확인한다.
- AC-4: 정상 종료·중단·공간 부족의 처리와 복구 범위를 명시하며 전원 장애 무손실을 검증 없이 주장하지 않는다.
- AC-5: 24시간 동작 시험은 선언한 쓰기/보존 예산으로 수행하며 모든 원본의24시간 전량 보존을 요구하지 않는다.

## 추가 수락 기준 — FR-018, 2026-10-26 Human 승인

AC-6~9는 옵션을 활성화하고 신호 연동·보호 계획을 설정한 구성을 전제로 한다. 기본 비활성 정책과 아래 검증 절차/세부 기준을 승인받았다. 실제 실행은 미완료다.

- AC-6: 사전 지정한 중요 파일 순위와 보호 범위를 기준으로 긴급 기록하며, 큰 일반 기록/느린 비필수 출력이 중요 파일 처리를 막는 범위를 계측한다. 기록별 보존 중요도와 파일의 긴급 우선순위는 구분한다.
- AC-7: 신호 발생부터 차단까지 전체 약 3초의 예산에서 전달 지연·안전 여유를 포함해, 선언한 최대 미동기화량의 중요 범위와 필요한 복구 메타데이터가 전원 차단 전 영속 동기화 완료되는지 확인한다. 측정 시작점을 로거 수신 시각으로 바꾸지 않는다.
- AC-8: 파일별 완료·실패·미완료와 기한 초과를 구분하고 실제 전원 차단/재기동 후 파일 내용·식별자·복구 범위를 대조한다. 전원 차단 직전 미기록 진단 정보의 보존을 전제하지 않는다.
- AC-9: 장비/OS/UPS/SSD·부하·최대 보호량·신호 지연 조건과 결과를 함께 남긴다. 모의 신호·이미 진행 중인 IO·신호 중복/지연·공간 부족/쓰기 장애를 포함하며 무제한 전량 저장이나 모든 환경의 시간 보장을 주장하지 않는다.
- AC-10: 기본 비활성 상태에서 전원 이상 입력으로 이 기능의 긴급 저장 전환이나 전용 자원 예약이 발생하지 않고 일반 기록/종료 계약을 유지하는지 확인한다. 활성화 구성의 동작과 구분해 검증한다.

## 미정/검토 사항

요구사항 §12의 수치는 승인된 설계용 초기 기준선이며 실측 보장값은 아니다. 구체 장비·데이터 계약·실패 정책·API/제품·판정 오차는 OQ-002~005의 보완 계획에 따라 확정하며, 이 Story의 요구/AC 승인과 실제 구현 완료·성능 검증 통과를 구분한다.
