# US-004 — 운영 중 한계 확인과 개발자 기록량 조절

- 관련 Intent: INT-001
- 관련 Milestone: 없음
- 상태: Approved — 2026-10-25 Human 「확정」으로 설계 기준선/AC 승인. 구현·검증 전
- 우선순위: Must(기능 방향 기준)
- 관련 요구사항: FR-014·016·017 / NFR-006
- 갱신: 2026-10-25 / AI

## 사용자 요구

개발자는 별도 측정 준비 부담 없이 사용 중 부하와 병목을 확인하고 로그량·주기·대상을 조절해 효과를 다시 확인하기를 원한다.

## 수락 기준 — 설계 기준선

- AC-1: 채널/출력별 입력·완료량·지연·미처리량·손실과 관련 자원 관측을 제공한다.
- AC-2: 사용률 분모는 같은 조건의 검증된 능력이며 기준 미측정/변경/만료와 관측·검증·추정을 구분한다.
- AC-3: 버퍼 포화·출력 정지 흡수·디스크 잔여·순환 보존 창을 각각 의미에 맞게 표시한다.
- AC-4: 개발자 조절 전후의 설정·부하·관측 구간을 연결해 완료량·지연·자원·의도한 생략과 예상치 못한 손실을 비교한다.
- AC-5: 간편 점검은 선언한 부하·자원·시간 안에서 수행하고 짧은 시험을 지속 성능 보장으로 확대하지 않는다.
- AC-6: 계측 자체의 CPU·메모리·호출 지연 영향을 기록한다. 허용 오차와 비용의 수치는 설계에서 정한다.

## 미정/검토 사항

요구사항 §12의 수치는 승인된 설계용 초기 기준선이며 실측 보장값은 아니다. 구체 장비·데이터 계약·실패 정책·API/제품·판정 오차는 OQ-002~005의 보완 계획에 따라 확정하며, 이 Story의 요구/AC 승인과 실제 구현 완료·성능 검증 통과를 구분한다.
