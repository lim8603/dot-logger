# ADR-005 — 초기 설계 기준선과 미결 사항의 설계 이월을 확정한다

## 상태·날짜

`Accepted` · 2026-10-25 · 결정자: Human

관련 Intent: INT-001. 관련 요구사항: FR-001~017·NFR-001~006. 수락 시나리오: US-001~004.

## 맥락과 승인 근거

프로젝트 목표·핵심 가치와 초기 기능/성능 사양을 정리한 뒤 Human에게 초기 기준선·문서 계획을 사용하고 미정 항목을 설계에서 확정하는 조건의 Design 전환을 확인했다. Human은 **「확정」**이라고 답했다. 승인 대상은 요구사항 §12·15, Story/AC와 문서 계획이며 개별 기술 후보의 채택이나 성능 달성 판정은 아니다.

## ADR 필요성

검증할 성능·자원 기준, 기능 범위·수락 기준, 미결 사항의 확정 시점은 설계 선택과 구현/검증 비용 및 운영 계약에 함께 영향을 주므로 기록한다. ADR-001·003·004를 대체하지 않는다.

## 결정

1. [요구사항 §12](../../02_project_definition/requirement_spec.md#12-초기-통합-사양안--제안-01)의 조건부 성능·자원 목표와 R1/P0~P6를 **설계 기준선**으로 사용한다. 원본1 GB/s급·소형10만건/s 혼합,32생산자·16파일·128채널 검증과 R1 버퍼2 GiB/용량 비교 등이 포함된다. 고정 제품 기본값이나 장비 독립적인 보장값으로 해석하지 않는다.
2. 프로젝트 목표·핵심 가치·Must 기능과 US-001~004의 수락 조건을 설계 기준으로 삼는다. 운영 중 부하/한계 확인·간편 점검·개발자 기록량 조절·전후 효과 확인을 핵심에 포함한다. 구체 UI/API·질문 프리셋/추천 상세는 별도 설계 사항이다.
3. [요구사항 §15.4](../../02_project_definition/requirement_spec.md#154-미결을-설계에서-확정할-보완-계획)의 OQ-002~005와 ONB-001 보완 계획을 승인한다. 실제 장비/제어 부하, 중요도·포화·내구성, DB/형식/프로토콜·배치·클라이언트, 계측 비용/오차 등은 명시한 설계 리뷰·계약·구현 전 시점에 확정한다. 해결되지 않은 기술 값을 해결됨으로 닫지 않는다.
4. [산출물 계획](../../02_project_definition/deliverable_plan.md)의 필수/권장 범위와 단계별 수집 계획을 승인한다. 이는 공식 문서 생성·외부 배포·릴리즈 요청이 아니다.
5. 기존 요구·ADR·스토리/수락 조건·리스크·문서 계획을 기준으로 Gate 1·2를 재점검하고 **Design 단계로 전환**한다. 승인된 미결 이월과 후속 수집 조건을 유지한다.

## 승인에 포함되지 않는 것

실제 장비의 성능 측정·검증 통과, 모든 옵션 조합의 무손실·고정 지연, 특정 파일 형식/DB/프로토콜/큐 라이브러리의 채택, 미검토 API/알고리즘 확정, 구현·의존성 설치·부하 시험·배포는 이번 승인으로 수행/완료된 것으로 취급하지 않는다.

## 후속 행동

도메인/모듈·자원/실행 경계와 핵심 API의 소유권·수락·출력별 완료·실패·조절 계약 초안을 작성한다. 주요 기술/설계 선택은 권한 매트릭스와 ADR 기준에 따라 별도 검토한다. 새로운 장비·부하 근거로 초기 목표를 바꿀 때는 조건·사유·검증 범위를 함께 갱신한다.

## 2026-10-31 검증 방법·시점 갱신

Human 승인 [ADR-011](ADR-011_local_pc_simulated_ups_verification.md)에 따라 실제 장치 수락은 현재 Ubuntu PC 실측으로 대체하고 UPS는 시뮬레이션 결과로 판정한다. GitHub native는 저장소 공개 완료 후 실행한다. 이전 실제 장비/실물 UPS 필수·native 실행 시점은 이 범위에서 갱신하며 기능/완료/오류/예산 계약은 유지한다. 시뮬레이션 수락을 물리 전원 소실 내구성의 관측 증거로 표시하지 않는다.
