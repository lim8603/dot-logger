# ADR-004 — 입력·처리 성능과 저장 예산·정책을 분리한다

## 상태·날짜

`Accepted` · 2026-10-25 · 결정자: Human

관련: INT-001, [ADR-003](ADR-003_configurable_policies_and_defaults.md). ADR-003의 정책 옵션과 RT 호출 계약은 유지한다.

## 맥락과 결정 요인

Human은 Q6의 센서 구성이 순간 처리 능력의 설계 가정이며, 저장량은 하드웨어에 따라 별도로 보아야 한다고 설명했다. SSD를 기본 저장 매체로 가정하고, Q7의 연속 전량/순환·이벤트 보존도 옵션으로 제공하라고 요청했다.

성능 계약, 자원 구성, 저장·장애 정책의 경계를 장기적으로 정하므로 ADR로 기록한다. 24시간 원본 전량 보존은 기존에도 요구로 확정되지 않았으며, 이번 결정은 그 구분과 옵션 지원을 명확히 한다.

## 결정

1. **입력·처리 성능과 영속 저장 성능을 구분한다.** 순간 입력·처리량은 입력 크기·발생률·지속시간·메모리 예산·처리 단계와 함께 평가한다. 실제 저장은 SSD·파일 시스템·동시 부하·동기화 정책을 포함해 별도로 평가한다.
2. **24시간 동작은 서비스 신뢰성 목표다.** 모든 원본을 24시간 전량 보존해야 한다는 요구가 아니다.
3. **저장 모드는 설정 옵션으로 제공한다.** 연속 기록, 용량/기간 제한을 둔 순환 기록, 이벤트 전후 구간 보존을 지원하는 방향으로 설계한다. 기본 모드·보존 기간·용량·이벤트 창은 아직 미정이다.
4. **SSD를 기본 저장 매체로 가정한다.** SATA/NVMe, 모델·용량·대역폭·쓰기 수명은 미선정이다.
5. **저장 예산은 배포 환경별로 정한다.** 버퍼·파일 사용량·보존 기간과 포화 동작의 설정 범위를 설계한다. 구체 기본값과 자동 감지 여부는 미정이다.
6. **RT 호출의 무대기와 중요도 정책은 유지한다.** 수락 실패·선택적 폐기·저장 실패는 구분해 관측할 수 있어야 한다. 구체 폐기 규칙과 관측 API는 후속 설계한다.

## 평가 지표와 미정 범위

수집 수락량/실패량, 직렬화 등 지정 단계까지 처리한 양과 지연, 메모리 점유, 파일 쓰기량/지연, 영속 동기화 완료량/지연, 정책에 따른 폐기량과 조회·재생 동시 부하를 구분해 기록한다.

이는 평가 축의 합의다. 수치·평가 장비·상세 테스트 전략은 미정이며 구현·성능 실측은 수행하지 않았다. 앞선 553~968 MB/s와 48~84 TB/24h는 조건부 계산 예시로 보존하고 성능 SLA·SSD 요구·운영 보존량으로 사용하지 않는다.
