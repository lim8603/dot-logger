# ADR-007 — 내장형 Ports and Adapters와 제한된 처리 파이프라인

- 상태: Accepted — 2026-10-26 Human 「너의 추천에 따를께」
- 날짜: 2026-10-26
- 관련: INT-001 / MS-001 / FR-001~014·016~018 / NFR-001~007
- 승인 경계: 설계 패턴·실행 구조 채택 승인. 기술별 채택·세부 API·수치 기본값은 별도 검토한다.
- ADR 필요성: 프로세스 경계에 따른 RT 비용·장애 격리·배포 비용이 장기적으로 결합된다.

## 맥락

1인 개발이며 Rust 라이브러리를 dot-probe에 먼저 통합한다. RT 수집은 대기·할당·I/O를 피해야 하고, 파일·DB·원격·조회 장애와 예산을 구분해야 한다. Human은 2026-10-26 Rust 클라이언트 API + CLI로 시작하고 dot-probe 기존 화면에서 연동하는 형태를 선택했다.

## 대안

| 대안 | 장점 | 비용·한계 | 판단 |
|------|------|-----------|------|
| 내장형 모듈 구조 + Ports and Adapters + 생산자/소비자 파이프라인 | IPC 없이 풀 소유권 전달, 파일/DB/시각을 교체·대역 테스트 가능, 한 라이브러리 배포 | 앱과 주소 공간 공유, 프로세스 abort/OOM까지 격리할 수 없음 | 권고 |
| 독립 수집 데몬 + IPC/공유 메모리 | 프로세스 장애·권한 분리 | 공유 메모리 수명·크래시 회수·프로토콜·배포 관리가 추가됨 | 독립 장애 격리가 실제 요구가 될 때 재검토 |
| 일반 비동기 런타임에 모든 기록을 태스크로 제출 | 적은 코드로 초기 구현 가능 | enqueue/스케줄링/할당·backpressure가 RT 호출 계약과 결합 | RT 경로에는 부적합, 네트워크 어댑터 내부에는 가능 |

## 권고하는 결정

1. 잘 알려진 **Ports and Adapters(헥사고날 아키텍처)**를 라이브러리의 경계에 적용한다. 내부는 고정 용량의 생산자/소비자 파이프라인으로 구현한다. 독립 서비스·범용 플러그인 로더·도메인별 다수 crate는 첫 범위에 넣지 않는다.
2. dot-probe 프로세스에 라이브러리를 연결한다. 생산자마다 사전 등록한 전용 핸들과 SPSC 입력 경로를 두고, 비-RT 워커가 분배·출력·회수한다. RT에서 async executor를 호출하지 않는다.
3. 파일·DB·원격 출력별 대기열/작업/재시도 상한을 둔다. 단일 dispatcher가 파일 쓰기를 직접 수행하지 않는다. 파일별 writer 소유권을 명확히 하되 worker 수는 구성한다.
4. 클라이언트 API + CLI를 별도 패키지로 제공하고, 라이브러리의 선택적 서버 어댑터에 연결한다. 네트워크/DB 없이 파일 수집·오프라인 읽기를 사용할 수 있어야 한다.
5. CPU affinity는 간섭 감소 수단이다. IRQ·커널 작업·공유 캐시·메모리 대역폭까지 완전 격리한다고 표현하지 않는다. Tier 1의 수치는 승인된 조건부 목표이며 장비별 검증 이후에만 달성을 표시한다.

## 결과와 검증

- 수집 코어가 파일·DB·네트워크 구현에 의존하지 않도록 모듈 의존 방향을 검사한다.
- 느린 writer가 dispatcher를 막지 않는지, 선택 출력 정지가 다른 경로의 무제한 메모리 증가를 만들지 않는지 검증한다.
- 같은 프로세스의 메모리 손상/abort는 격리하지 못한다. 복구 가능한 I/O 오류의 전파 차단과 구분한다.
- 단일 dispatcher가 P3 목표의 병목이면 측정 결과로 shard를 추가한다. 처음부터 분산 시스템을 도입하지 않는다.
