# 도메인 용어집

- 프로젝트: dot-logger / INT-001
- 상태: 대화·승인 ADR에서 추출한 용어. 구체 타입/API는 설계 단계에서 결정한다.
- 갱신: 2026-10-25 / AI

## 용어 정의

| 용어 | 정의 | 근거 |
|------|------|------|
| 생산자 | 기록을 제시하는 애플리케이션 스레드/호출 주체 | 요구사항 FR-012 |
| 논리 채널 | 스레드와 독립적으로 데이터 목적·종류를 구분하는 기록 단위 | 요구사항 §11 |
| 출력 대상 | 파일·DB·원격 구독 등 기록을 전달할 목적지. 실제 제품/프로토콜은 미선정 | 요구사항 FR-003~006·013 |
| 로그 레벨 | 진단 메시지의 심각도/상세도 분류 | ADR-003 |
| 보존 중요도 | 공간 부족 시 보존 판단에 사용하는 로그 레벨과 독립적인 중요도 | ADR-003 |
| 수락 | 로거가 기록 처리를 받아들인 상태. 저장 완료와 구분 | ADR-003·004 |
| 완료 경계 | 입력 수락·파일 쓰기·영속 동기화·수신 활용 등 평가/확인의 도착점 | 요구사항 §10·12 |
| 미처리량 | 수락했으나 해당 완료 경계까지 끝나지 않은 records/bytes | 요구사항 §13 |
| 관리 버퍼 | 로거가 보유하거나 수명을 연장한 원본 및 큐·작업·송신/조회 등에 쓰는 제한된 메모리 | 요구사항 §12.3 |
| 순환 보존 | 용량/기간 제한에 따라 과거 기록을 교체하는 보존 방식 | ADR-004 |
| 이벤트 구간 보존 | 지정 사건의 전후 구간을 보존하는 방식 | ADR-004 |
| 기준 처리 능력 | 같은 장비·기능·부하 조건에서 지연·자원·손실 조건을 만족하며 측정한 지속 처리 범위 | 요구사항 §13.2 |
| 관측·검증·추정 | 일상 실행의 관측, 선언된 시험의 검증, 가정에 의존한 예측을 구분한 결과 유형 | 요구사항 §13~14 |
| 기록량 조절 | 개발자가 기록 주기·대상·필터·샘플링 등을 선택해 부하와 정보량을 조정하는 행위 | 요구사항 FR-017·§13.5 |

## 도메인 규칙

| 규칙 | 기준 |
|------|------|
| RT 호출 | 버퍼 공간이나 저장/전송 완료를 기다리지 않으며 수락 실패를 관측할 수 있어야 한다 |
| 정책 기본값 | 무대기·중요 기록 우선·로그 레벨과 별도 보존 중요도 |
| 성능과 보존 | 입력/처리와 하드웨어별 지속 저장·보존 예산을 분리하며24시간 동작을 원본24시간 전량 보존과 동일시하지 않는다 |
| 결과의 의미 | 수락·쓰기·영속 동기화·수신 활용을 혼동하지 않고 추정값을 실측값으로 표시하지 않는다 |
| 조절의 주체 | 개발자가 조절하고 전후 효과를 확인한다. 자동 제한·설정 변경은 승인된 기본 동작이 아니다 |

## 미확정 사항

정확한 API/타입, 순서·소유권·영속 완료·포화 세부 계약은 요구사항 OQ-002~005와 설계 진입 검토안에 따라 상세화한다.
